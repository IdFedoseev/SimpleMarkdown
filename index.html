## Edit the page, not the source

Select any text and a toolbar appears — bold, italics, code, links. Type / for a menu of blocks: headings, lists, quotes, code. What you touch is the finished document; what lands on disk is clean Markdown — the same syntax you would have typed by hand.

## Every file gets a tab

Every open file gets a tab. Jump with ⌘1…⌘9 — nine always means the last tab, however many you have. Cycle with ⌘⌥←/⌘⌥→ or Ctrl+Tab. Close with ⌘W or a middle-click, the civilized way.

Quit and reopen: the session comes back. Switch away and back — each tab stays scrolled to where you stopped. Untitled notes are the one exception — unsaved things don't survive restarts. Press ⌘N for a fresh one; it lives in memory across tab switches until the save dialog gives it a filename. A dot on a tab means unsaved edits. Autosave clears it before you've worried.

## Diagrams live in the page

A mermaid block renders as the diagram it describes. The code stays hidden; the picture takes its place in the document. Click the ⤢ icon on it for a fullscreen viewer: zoom with the wheel, the buttons, or a double-click; pan by dragging; Esc to get out. Zoom runs 5% to 2000%. The viewer follows your system theme, dark included.

## Red pen, self-erasing

Press ⌘D — or the draw button — and sketch directly over the page. Red strokes on top of the document; nothing is written to the file. Made for pointing at things: a screen share, a review, a lively argument. Each stroke fades on its own after a timeout you pick — 3, 5, 10, 30, or 60 seconds. Five by default. Point, explain, let it disappear.

## Hot reload for documents

Edits save themselves 700 ms after you stop typing (an untitled note waits for its first ⌘S). ⌘S works too, if you enjoy pressing it. An unsaved dot in the title bar keeps the score. Meanwhile, files changed elsewhere — git pull, another editor, a script — appear within about two seconds, or the moment the window regains focus. External updates never overwrite your unsaved edits.

## A start screen with physics

No document open? Reader shows your recent files — up to twelve — as a loose cloud of chips. Drag them around; they bump, drift, and settle. A physics toy that doubles as a file picker. Click a chip and you are back in the document.

## Everything one keystroke away

Drop a file or an entire folder anywhere on the window.

Open
⌘O for a file, ⌘⇧O for a folder. Drag-and-drop accepts either, anywhere on the window.
New note
⌘N opens an untitled note; the save dialog gives it a home.
Sidebar
every file in the open folder one click away; ⌘\ hides it when you want width.
Search
⌘F highlights every match with an N/M counter; Enter, ⌘G or F3 for next, ⇧ for previous, Esc to close. Highlights update live while you edit.
System default
Make Reader the default app for Markdown once; double-clicking in Finder opens files in it.
Formats
.md, .markdown, .mdown, .mkd — editable. .txt — view only.

## Three steps to your first document

  1. Drop any .md file onto Reader

    Or press ⌘O. Double-click works too, once Reader is the default Markdown app.

  2. It opens rendered

    Like a PDF, not a text file full of asterisks.

  3. Click into the text and type

    The file saves itself. That is the whole tutorial.

## Questions

How is Reader different from other Markdown viewers?

Most Mac viewers are read-only. Reader treats the rendered page as the editor: you fix and restructure in place, and the file stays plain Markdown.

Will it mangle my files?

No. Edits are saved back as clean, standard Markdown — the syntax you would type by hand. Reader is also a young app, so keep git or Time Machine around for anything precious.

Can it edit plain text files?

No. .txt files open view-only. The editable formats are .md, .markdown, .mdown, and .mkd.

What does it cost?

Nothing. MIT license, forever. No trial, no locked features, no subscription.

Which systems does it run on?

macOS only.

What about Windows or Linux?

Not today. The license lets anyone try to change that; watch GitHub if you care to.
